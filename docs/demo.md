# Демонстрация

Из корня проекта с активированным окружением:

```bash
appeals doctor --live
appeals demo
appeals demo --fault
appeals queue
```

`doctor --live` проверяет OAuth и наличие настроенной модели. Оба демо используют провайдера из конфига; стандартный конфиг подключает реальный GigaChat.

| Сценарий | Ожидаемое поведение |
|---|---|
| `demo` | Поиск материала о доступе к кабинету, получение маршрута, черновик с источником; status=draft_ready |
| `demo --fault` | Три таймаута поиска, возврат ошибки модели, запрос передачи человеку; после подтверждения status=escalated и ticket_id |

Перед созданием задачи терминал показывает карточку действия. Введите `ПОДТВЕРЖДАЮ` для записи; другой ввод отменяет действие. `queue` показывает сохранённые результаты и связанные задачи. Технические события содержат имя инструмента, аргументы, попытки и результат.

Для демонстрации до трёх минут: кратко показать назначение и контракты, выполнить оба сценария, подтвердить передачу, показать ticket_id и конфиг провайдера. В кадре используются синтетические обращения; `.env` и заголовки авторизации не открываются.

## Повтор без дублирования

```bash
appeals run --text 'В подъезде сломан лифт' --request-id demo_same_appeal --trace
appeals run --text 'В подъезде сломан лифт' --request-id demo_same_appeal --trace
```

После подтверждения первого вызова повтор возвращает тот же ticket_id с deduplicated=true.

## Смена провайдера

```bash
appeals --config config/ollama.toml run --scenario account_normal --trace
```

Нужны запущенный Ollama, модель из конфига и `COMPATIBLE_API_KEY=ollama` в окружении. Провайдер, адрес API и модель задаются конфигурацией; логика агента общая.
