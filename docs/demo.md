# Демо ДЗ 1: обычный сценарий и ошибка

R13, R15, R16. Требуется живой запуск на занятии 16 ноября. Первая лекция также требует видео не более 3 минут. В запись включается настоящая модель; offline fixtures демонстрируют только код и не заменяют этот пункт.

## Подготовка до записи

1. Установить проект, заполнить локальный `.env`.
2. Выполнить `appeals doctor --live`, убедиться в доступности модели и лимита.
3. Выполнить `pytest -q` и live-eval минимум с тремя повторами, проверить неудачи.
4. Увеличить шрифт терминала. Не показывать `.env`, токен OAuth или сетевые заголовки.
5. Использовать только синтетические тексты. Открыть README и матрицу требований в редакторе.

## План записи (до 180 секунд)

| Время | Что показываем | Что говорим |
|---|---|---|
| 0:00–0:20 | Название и спецификацию | «Агент помогает сотруднику разобрать обращение, подготовить черновик с источниками или передать человеку» |
| 0:20–1:05 | `appeals demo` | «Модель сама выбрала инструменты. Видны фактические вызовы, источники и итоговая карточка» |
| 1:05–2:10 | `appeals demo --fault` | «Справочный инструмент вернул timeout. Повторы ограничены. Модель получила ошибку и передала случай человеку» |
| 2:10–2:30 | Подтверждение, ticket_id и `appeals queue` | «Без подтверждения записи нет. После подтверждения задача сохранена. Повтор одного request_id не создаст дубль» |
| 2:30–2:50 | Конфиг GigaChat и альтернативы | «Провайдер и модель задаются в TOML, формат API переводит адаптер» |
| 2:50–3:00 | Тесты и матрицу | «Контракты, права, ошибки и ограничения проверяются автоматически; live-результаты приложены отдельно» |

Сетевые задержки провайдера могут не уложиться в тайминг. Сначала отрепетируйте; при записи можно убрать периоды ожидания с явным обозначением склейки. Не подменяйте ответ LLM записанным сценарием под видом live-вызова. На занятии готовьте полностью живое демо.

## Команды

```bash
appeals doctor --live
appeals demo
appeals demo --fault
appeals queue
```

При создании задачи в интерактивном терминале покажется точная карточка. Проверьте её и введите `ПОДТВЕРЖДАЮ`. В `demo --fault` три попытки чтения справочного инструмента искусственно завершаются timeout; реальный GigaChat продолжает отвечать по API. Если модель не вызывает поиск, trace это покажет и сценарий не следует объявлять успешным. Используйте eval для исправления такого поведения.

### Повтор действия без дубля

```bash
appeals run --text 'В подъезде сломан лифт' --request-id demo_same_appeal --trace
appeals run --text 'В подъезде сломан лифт' --request-id demo_same_appeal --trace
```

На первом запуске подтверждается запись. На втором успешный tool result содержит `deduplicated=true` и тот же ticket_id. Это один и тот же локальный объект, а не новый гражданин.

### Смена провайдера

```bash
appeals --config config/ollama.toml run --scenario account_normal --trace
```

До демо должны быть установлены Ollama и модель с поддержкой tools. Не утверждать проверку этого пункта на реальном backend, если выполнен только HTTP-contract тест.

## Запись видео на Mac

Используйте встроенную запись экрана: `Shift+Command+5`, выберите область с терминалом и редактором. Готовый файл назовите `hw1_live_demo.mp4`/`.mov`; проверьте длительность, читаемость команд и отсутствие ключа. Если видео слишком велико, разместите его в разрешённом преподавателем хранилище или GitHub Release и добавьте ссылку в сдачу. В `docs/validation.md` укажите фактическую ссылку и дату после записи.
