Новостная публикация о возможностях кабинета маркирована сайтом как архивная. Из неё используется общее описание функциональности, без фиксации расположения кнопок и сроков. Перед реальной эксплуатацией требуется повторная проверка текущей справки сервиса. Датированные региональные новости о налоговых уведомлениях и ЕНС были сверены с текущими тематическими страницами; в базе оставлены ссылки на тематические страницы.

В проекте используются учебный классификатор и синтетические примеры. Юридические сроки, право на вычет, суммы налога и решение о перерасчёте агент не рассчитывает.

Публичная страница ФНС об обращениях содержит ссылку на порядок по 59-ФЗ и правила обработки персональных данных. Закон 152-ФЗ является основанием ограничения на реальные персональные данные в проекте; проект не заявляет сертифицированного соответствия этому закону. Ключевые архитектурные меры: синтетические обращения, минимизация передаваемых полей, маскирование распространённых реквизитов, исключение runtime/секретов из Git и отсутствие отправки официальных писем.

## Технические первоисточники

- [Авторизация GigaChat API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api): OAuth, scope, Bearer и адрес API.
- [Генерация аргументов пользовательских функций](https://developers.sber.ru/docs/ru/gigachat/guides/functions/generating-arguments-for-custom-functions): native functions/function_call, роль function, сохранение functions_state_id.
- [Работа с функциями](https://developers.sber.ru/docs/ru/gigachat/guides/functions/overview).
- [Ollama: OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility): альтернативный Chat Completions backend.

В коде нет автоматической загрузки сторонних сайтов по указанию модели. Поиск ограничен локальным набором, а URL итоговой карточки берутся из найденных записей. Это делает демонстрацию воспроизводимой и не позволяет модели подставить произвольный внешний источник.
