Дата: 15.11.2026. Статусы относятся к проверенной версии и не являются обещанием оценки преподавателя.

## Выполнено в среде разработки

- Реализованы три предметных инструмента, полный цикл, два настоящих сетевых адаптера и отдельный scripted backend.
- 21 синтетический сценарий, по три независимых повтора в offline harness.
- Проверены права, подтверждение, отмена, запись/дедупликация, schema validation, ошибки, таймауты, некорректные источники и лимиты.
- HTTP-contract тесты проверяют native OAuth/функции/состояние GigaChat и формат альтернативного API без реальных ключей.
- Чистое окружение Python 3.12, без наследования глобальных пакетов: установка по `requirements-dev.lock` и editable install прошли.
- **156 тестов прошли**, lint и проверка форматирования прошли (после разбора финальных 105 запусков).
- **21 сценарий × 3 повтора = 63 offline прогона, все ожидаемые проверки прошли.** Это результат harness, не accuracy реальной LLM. [Машиночитаемые результаты](offline_results.json).
- Source distribution и wheel успешно собраны через `python -m build --no-isolation`.
- GitHub Actions успешно прошёл на Python 3.11, 3.12 и 3.13 для первой реализации. [Актуальные прогоны](https://github.com/alexey077/agent_systems/actions) показывают состояние последующих коммитов.

## Попытка реального подключения 15.11.2026

`appeals doctor --live` выполнил ограниченные попытки подключения и завершился контролируемой ошибкой недоступности провайдера. Диагностические запросы **без авторизационных данных** к OAuth endpoint, текущему и прежнему адресу списка моделей получили HTTP 503, `server=envoy`, с сообщением об ошибке соединения с upstream до получения его заголовков. Это не ответ о неверном ключе. Список моделей, access token и ответы LLM не получены, поэтому реальные оценки качества не вычислялись.

Обнаруженная при первом запуске зависимость SOCKS-прокси включена в lock-файл, ошибка отсутствующего транспорта обрабатывается как configuration error. Проверка TLS не отключалась. Осталось повторить запуск из сети, доступной серверам провайдера; дополнительные Client ID/Secret не устраняют сетевую недоступность.

## Исправление TLS и диагностики 15.11.2026

Связанные требования: R10–R12 и R14; контракты трёх предметных инструментов не менялись. Исправлена потеря причины транспортной ошибки: раньше TLS, DNS и сеть ошибочно отмечались как timeout, а конечное сообщение скрывало даже HTTP 503. Теперь ошибки различаются, а `doctor --live` сохраняет результаты пройденных этапов и завершается ненулевым кодом при сбое или недоступной модели.

В native GigaChat автоматически подключается публичный корень из официальной инструкции провайдера. Сохраняются системные корни, добавляется `certifi`; глобальные хранилища не изменяются, `CERT_REQUIRED` и проверка имени включены. [Происхождение и SHA-256 сертификата](tls.md).

Проверено: 93 теста, включая TLS-корни/отпечаток, запрет отключения проверки, вложенную ошибку сертификата без повторов, DNS/сеть/прокси/таймаут с ограниченными повторами, сохранение HTTP-статуса, диагностику этапов, недоступную модель и отсутствие секретов в выводе.
