# Контракты инструментов

Требования R02–R08. Имена, схемы и исполняемые функции: `src/citizen_agent/tools.py`, `models.py`. В API передаются те же JSON-схемы, которыми проверяются аргументы. В каждой карточке ровно восемь полей семинара. JSON-примеры используют синтетические идентификаторы.

## 1. search_knowledge_base

**1. Имя:** `search_knowledge_base`.

**2. Описание:** ищет публичные справочные материалы ФНС в локальной атрибутированной базе. Вызывать, когда нужно основание для черновика. Использовать короткий запрос без персональных данных. Не применять для личного статуса гражданина, маршрутизации и действий. `other` означает общий поиск по базе. Отсутствие совпадений означает отсутствие основания, а не отрицательный ответ на вопрос гражданина.

**3. Аргументы:**

| Поле | Тип / границы | Обязательность |
|---|---|---|
| query | Строка 3–400 символов | Да |
| category | account_access, tax_notice, property_error, deduction, tax_debt, other | Да |
| limit | Целое 1–5, по умолчанию 3 | Нет |

Лишние поля запрещены, строка `"3"` и bool вместо целого не принимаются. Идентификатор источника, клиент или путь к файлу не являются аргументами.

**4. Что задаёт код:** разрешённый путь базы, набор источников, текущая организация/сессия, права чтения, таймаут, лимиты результата и повторов. Тексты базы не могут менять системные правила.

**5. Результат:**

```json
{
  "ok": true,
  "sources": [{
    "source_id": "fns_account_access",
    "title": "Как получить доступ в Личный кабинет налогоплательщика",
    "url": "https://www.nalog.gov.ru/rn77/fl/interest/lk-account/",
    "category": "account_access",
    "text": "Краткий пересказ публичного материала",
    "checked_at": "2026-11-15"
  }],
  "total_found": 1,
  "truncated": false
}
```

Максимум 5 фрагментов, общий сериализованный результат не больше `max_result_chars` (9000 по умолчанию). Результат не содержит ключей и реквизитов клиента. Пустой `sources=[]` — нормальная выдача без совпадений.

**6. Ошибки:** `validation` — неверные поля; `forbidden` — нет прав; `timeout`/`service_unavailable` — чтение не удалось после попыток; `invalid_result` — отсутствующий/повреждённый файл или некорректная структура; `result_too_large` — превышение размера; `unsafe_content` — распознана посторонняя команда. В каждой ошибке есть понятные `message` и `hint`, без исходного стектрейса.

**7. Тип:** чтение. Подтверждение не требуется. Побочных эффектов в предметной системе нет. Вызов пишется в техническую трассу.

**8. Отказ:** до трёх технических попыток только для временной недоступности и таймаута. Новую смысловую формулировку выбирает модель. Пустой/непригодный результат требует уточнения либо передачи человеку. Нельзя сочинять источник или считать отсутствие совпадений доказательством факта.

## 2. get_routing_rules

**1. Имя:** `get_routing_rules`.

**2. Описание:** возвращает учебную очередь и правила приоритета для одной определённой темы. Вызывать после понимания темы. Не используется как база нормативных ответов. Результат прямо маркирован как учебный; адресаты не выдаются за официальные отделы ФНС. Для `other` адресат отсутствует.

**3. Аргументы:** единственное обязательное поле `category`, строго из того же enum, что в поиске. Лишние поля и несуществующие категории запрещены.

**4. Что задаёт код:** путь к справочнику, текущая организация/сессия, права, допустимые очереди и правила приоритета. Модель не выбирает произвольный email, организацию или существующий ticket.

**5. Результат:**

```json
{
  "ok": true,
  "category": "account_access",
  "recipient": "Доступ к личному кабинету (учебная очередь)",
  "priority_rules": {
    "default": "normal",
    "high_markers": ["срок завтра", "сегодня последний день", "до конца дня"],
    "explanation": "Учебный приоритет обработки, не юридическое определение срочности."
  }
}
```

Одна компактная запись, общий предел размера действует так же. Приоритет `high` в итоговом ответе дополнительно проверяется приложением по этим маркерам в тексте обращения.

**6. Ошибки:** `validation`, `forbidden`, `not_found` для `other`/отсутствующего маршрута, `timeout`, `service_unavailable`, `invalid_result`, `result_too_large`. Общая структура `ok=false`, `error.type/message/hint`.

**7. Тип:** чтение, без подтверждения и предметных изменений.

**8. Отказ:** временная ошибка повторяется ограниченно. При отсутствии маршрута модель передаёт человеку и не создаёт адресата. Плохая структура не воспринимается как успешный результат.

## 3. escalate_to_operator

**1. Имя:** `escalate_to_operator`.

**2. Описание:** создаёт локальную задачу ручного разбора текущего обращения. Вызывать при недостатке оснований, неоднозначности, личном статусе, неподдерживаемой теме или отказе сервиса. Требуются краткая сводка и причина. Не отправляет официальное письмо и не регистрирует обращение в государственной системе. Успех можно сообщать только после результата с сохранённым `ticket_id`.

**3. Аргументы:**

| Поле | Тип / границы |
|---|---|
| reason | ambiguous, out_of_scope, missing_evidence, tool_failure, personal_data_required, security, limit_reached, invalid_answer, provider_failure, manual_review |
| summary | Строка 5–600 символов без персональных данных |

Оба поля обязательны. `confirmed`, `request_id`, `actor_id`, организация и очередь в аргументах запрещены.

**4. Что задаёт код:** текущие `Session.request_id`, `actor_id`, `organization`, право `can_escalate`, очередь `manual_review`, идемпотентный ключ организации/обращения, результат trusted UI callback. Подтверждается точная карточка действия. Модель не может выдать согласие от имени человека.

**5. Результат:**

```json
{
  "ok": true,
  "status": "escalated",
  "ticket_id": "review_0123456789abcdef",
  "reason": "missing_evidence",
  "summary": "Недостаточно данных для ответа",
  "confirmed_at": "2026-11-15T18:00:00+00:00",
  "deduplicated": false
}
```

Повтор одного намерения возвращает существующий ticket с `deduplicated=true`, не создавая дубликат и не меняя ранее подтверждённую причину. Отмена: `{"ok":true,"status":"cancelled","cancelled":true}`; приложение останавливает повторную передачу после отказа.

**6. Ошибки:** `validation`; `forbidden`; `confirmation_required`, если UI подтверждения не предоставлен; `storage_error`, если сохранение не подтверждено; `internal` — контролируемая непредвиденная ошибка. Нельзя интерпретировать ошибку записи как успешную передачу.

**7. Тип:** действие с локальным побочным эффектом. Проверка прав, интерактивное согласие, SQLite-транзакция, уникальность `(organization, request_id)`, журнал `confirmed_by`. Это отдельный механизм от обычного сохранения результата обработки.

**8. Отказ:** автоматически не повторяется. При отмене записи нет. При неопределённом результате оператор проверяет очередь; повтор с тем же request_id безопасен благодаря уникальности. Если создать задачу невозможно, итог имеет `needs_human=true`, но без ложного утверждения о регистрации. Автоматическое подтверждение доступно только внутри тестового eval-harness с синтетическими данными и не используется обычными командами `run/demo`.

## Общая ошибка

```json
{
  "ok": false,
  "error": {
    "type": "validation",
    "message": "Аргументы не соответствуют схеме",
    "hint": "Исправь поля по схеме",
    "fields": [{"field":"limit","type":"less_than_equal","message":"Input should be less than or equal to 5"}]
  }
}
```

Для неизвестной функции реестр возвращает `unknown_tool`. Любое выполнение проходит через Executor. Аннотация или текстовое обещание модели не может обойти проверку.
