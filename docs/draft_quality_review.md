# Содержательная проверка второго реального прогона

Дата: 15.11.2026. Проверен предоставленный пользователем полный after-fix `report.json` для кода `0ee219f`: 63 результата, 27 непустых черновиков, 36 карточек ручного разбора. Метод — проверка ассистентом каждого текста по использованному фрагменту базы этой версии; спорные места дополнительно сопоставлены с официальными страницами ФНС. Это не независимое исследование с людьми и не универсальный автоматический фактчекер.

Исходный результат **63/63 по пяти автоматическим критериям** подтверждён. Все 27 ссылок/IDs соответствуют базе. У 36 ручных карточек пустой черновик и согласованные status/ticket_id. Дополнительная проверка поля priority по всем 63 результатам также успешна. [Санитизированный аудит каждого результата и SHA-256 исходного файла](gigachat_after_fix_quality_audit.json).

## Пять черновиков требуют правки

| Сценарий / повтор | Наблюдение | Исправление |
|---|---|---|
| priority_high / 1 | Исходное условие об отсутствии бумажного письма заменено выводом о наличии письма | Сохранять условие и отрицание исходного фрагмента; проверка отклоняет известную подмену |
| priority_high / 3 | Добавлен общий правовой вывод об обязанности уплаты, которого нет в выбранном фрагменте | Удалить неподтверждённый вывод; это не заключение о его истинности для всех юридических ситуаций |
| debt_normal / 1 | Продублирован источник с придуманным названием; название раздела интерфейса отсутствует во фрагменте | Источник выводит приложение, а черновик содержит только подтверждённые действия без новых названий разделов |
| debt_normal / 2 | В текст попал SOURCE_ID, добавлены блок источника и ограничение места обращения | IDs остаются только в структурированном поле; неподтверждённое ограничение места исключается |
| debt_normal / 3 | Словами «там же» запись на приём приписана личному кабинету | Уточнён источник: вопрос задаётся в кабинете, запись на приём относится к отдельному официальному сервису |

Остальные 22 черновика не требуют обязательной содержательной правки по принятой процедуре. В 12 ответах про восстановление доступа есть редакционное пожелание: рекомендовать обращение без обещания гарантированного результата. Основной способ действия и требование документа подтверждаются использованным источником.

Фрагмент ЕНС уточнён по официальной странице; версия базы — `2026-11-15.quality-review`. Наличие найденного источника само по себе не доказывает, что каждое предложение черновика передаёт его правильно.

## Реализованные проверки

`draft_quality_issue` отклоняет служебные маркеры и дублированные блоки источников, неподтверждённое ограничение места обращения и добавленное утверждение об обязанности. Для известных примеров проверяется сохранение условия об отсутствии письма и различие каналов кабинета/сервиса записи. Эти правила покрывают наблюдавшиеся ошибки; они не заменяют проверку остальных возможных фактических утверждений.

На исходном фрагменте новые правила отклоняют четыре проблемных черновика. С уточнённым источником ЕНС отклоняются все пять; 22 остальных прежних черновика продолжают проходить эти ограниченные проверки. Регрессионные тесты показывают возврат ошибки модели и принятие исправленного текста. Это проверка программы на сохранённых примерах, а не новый результат GigaChat.

## Версия оценки

Прежние отчёты сохраняют свой результат по пяти критериям. В `evaluation_schema_version=2` к ним добавлен **priority**, отдельно выводится `priority_accuracy`, а `check_names` перечисляет все шесть проверок. Для priority_high явно задано high, для остальных случаев используется normal. Исходные 21 текст и все прежние ожидания сохранены; критерии стали строже.

Следующий реальный прогон нужно сохранить отдельно:

```bash
appeals evaluate --repeats 3 --output runtime/gigachat_quality_fix/report.json
```

Результат после этих изменений ещё не получен. Альтернативный провайдер, запись видео и выступление остаются отдельными пунктами сдачи.
